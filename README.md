# Route Builder

Мобильное приложение для диспетчера курьерского депо: выбор остановок,
количество посылок, обязательные инструкции и создание маршрута.
Интерфейс — английский LTR. Целевая платформа проверки — iOS.

## Требования

- Node.js **22.13.x или новее**, npm.
- Expo SDK **58**, React Native **0.88**, TypeScript; версии закреплены в lockfile.
- Совместимый Expo Go либо iOS Simulator с установленным Xcode.

## Запуск

```bash
npm ci
```

В первом терминале из корня проекта:

```bash
node server.js
```

Во втором терминале:

```bash
npx expo start
```

Для проверенного запуска на симуляторе:

```bash
npx expo start --ios --lan
```

На физическом iPhone компьютер и телефон должны быть в одной сети;
отсканируйте QR Expo Go. Адрес API задаётся **только через конфигурацию
[src/config/api.ts](src/config/api.ts)**. По умолчанию это `http://localhost:4000`
для симулятора. Для телефона задайте LAN-IP компьютера:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.10:4000 npx expo start --lan
```

Подставьте реальный IP и перезагрузите приложение после изменения адреса.
`localhost` на телефоне означает сам телефон. Адрес Metro и адрес API различаются.
`EXPO_PUBLIC_API_URL` содержит публичный адрес, не секрет. При проблемах подключения
проверьте доступность порта 4000 и локальную сеть.

Проверенная среда: iPhone 17 Pro Max Simulator, iOS 26.0, Expo Go 58.0.7.
Запросы HTTP из приложения работали без дополнительных ATS-исключений в app.json.
Нативные каталоги вручную создавать не требуется. Проверка физического устройства
и удобства работы стоя одной рукой пока не проведена.

## Использование

1. Выберите One stop или Multi-stop route и нужные адреса. Пилюля N× меняет
   количество; изменения применяются кнопкой Save.
2. Continue открывает инструкции. Заполните каждую карточку: максимум 200 единиц
   UTF-16; пустые и пробельные строки блокируют отправку. Clear all очищает одну
   инструкцию, Remove from route удаляет остановку.
3. Finish instructions создаёт маршрут. Во время запроса редактирование заблокировано.
   Успех показывает проверенный id, New route начинает новый черновик.

Состояние хранится в памяти текущего запуска; после перезапуска оно не восстанавливается.

## Преднамеренные ошибки mock API

server.js неизменяем. Счётчик запросов общий: при запросе справочника кратное 9
значение даёт 500, кратное 14 — 503 с Retry-After: 2 (проверка 500 идёт первой).
Более 30 запросов за минуту с одного IP дают 429. Поиск регистрозависим и использует
серверный q; debounce — 400 мс. Retry становится доступен после срока ожидания,
автоматических повторов нет.

POST не идемпотентен: если ответ потерян, маршрут мог уже создаться.
Повтор требует подтверждения риска дубля. Защита от быстрых нажатий блокирует
одновременные отправки, но не отменяет этот риск осознанного повтора.
При расхождениях API.md и реального сервера приоритет имеет сервер.

## Проверки и архитектура

```bash
npx expo lint
npx tsc --noEmit
```

UI находится в src/screens и src/components, API-клиент — в src/api,
DTO/Domain — в src/types, состояние — в src/context. App.tsx переключает два экрана
через состояние. Клиент использует только GET /v1/stops и POST /v1/routes.
Зависимости устанавливаются через `npx expo install`, SDK без необходимости не обновляется.
