# API Contract: обязательное ядро Route Builder

Дата: 2026-10-27. Клиент потребляет существующий неизменяемый server.js.
Единственный источник baseUrl — src/config/api.ts. Сетевой транспорт — native fetch.
Это потребительский контракт клиента, не проект нового сервера.

## Разрешенные операции

| Операция | Путь | Назначение |
|---|---|---|
| GET | /v1/stops | Полный справочник и поиск |
| POST | /v1/routes | Создание маршрута |

Другие операции не входят в контракт клиента. Параметр zone не посылается.

## GET /v1/stops

Параметры: page — целое >=1, по умолчанию 1; page_size=50;
q — необязательная строка, trim перед кодированием. Регистр сохраняется.
Query кодируется через URLSearchParams; текст не конкатенируется в URL вручную.

Ответ 200:

```json
{
  "items": [{
    "id": "stp_1001", "name": "North Cafe",
    "address": "12 North Rd, Northbridge", "phone": "+44-20-7946-0188",
    "zone": "south", "packages_max": 5,
    "last_delivery_at": "2026-09-08T13:46:49.378Z"
  }],
  "page": 1, "page_size": 50, "total": 25,
  "total_pages": 0, "has_more": true
}
```

Это сокращенный пример формы, не обещание одной строки в полном справочнике.
Исходный набор содержит 24 записи. packages_max также бывает числовой строкой
и null; last_delivery_at — ISO без Z либо Unix-секундами; notes отсутствует/null.
items=null при поиске без результата и items=[] трактуются как пустой набор.

### Завершение и дедупликация

1. Запрос page=1, page_size=50; декодировать и нормализовать items.
2. Добавить записи в Map по id, сохраняя первое вхождение в рамках загрузки.
3. Если сырая страница короче 50, пуста или не дала новых id — завершить.
4. Иначе увеличить page и загрузить последовательно. Ошибка не равна пустой странице;
   частичный результат сохраняется и Retry продолжает неудавшуюся страницу.
5. total, total_pages, has_more не используются как условия продолжения.

Размер 50 дает полный текущий набор одним запросом; для неизвестного выросшего
набора гарантии полноты нет из-за ошибки сервера на второй странице.
Имя/адрес ищутся регистрозависимым includes; телефон — по цифрам q при >=3 цифрах.
Debounce 400 мс, отмена старого запроса, проверка requestId; очистка возвращает browse-кеш.
Неуспешный/устаревший запрос не удаляет выбранные точки и их инструкции.

## POST /v1/routes

Content-Type: application/json. Один POST на явное действие Submit.

```json
{
  "stops": [{
    "stop_id": "stp_1001", "packages": 2,
    "instructions": "Use the main entrance"
  }]
}
```

Клиент гарантирует непустой массив, уникальные известные stop_id, целые packages>=1,
соблюдение packages_max, непустой после trim текст длиной <=200 единиц UTF-16.
Передается неизмененный текст, а не результат trim. Сервер не обеспечивает эти
инварианты: Number(packages)||1, String(instructions||"").slice(0,200).

Подтверждение — только HTTP 201:

```json
{
  "id": "rt_2000",
  "stops": [{
    "stop_id": "stp_1001", "packages": 2,
    "instructions": "Use the main entrance"
  }],
  "status": "draft"
}
```

id непустой, status строго draft, порядок и все поля stops совпадают со snapshot.
Только после этой проверки UI показывает Route created. Создание не имеет
идемпотентности или операции чтения результата: ключ в заголовке не дает защиты.
Неправильный 201 — неизвестный результат; известный id сохраняется для диагностики,
повторный POST автоматически не выполняется.

## Ошибки и политика повторов

| Ответ / событие | Тело / заголовок | Поведение клиента |
|---|---|---|
| 400 POST | error=malformed_json | Ошибка запроса, исправление; без авто-Retry |
| 422 POST | error=validation_failed, fields.stops=required | Показать ошибку состава, сохранить ввод |
| 429 | error=rate_limited, Retry-After: секунды | Общий cooldown; Retry не раньше срока |
| 500 GET | error=internal_error, request_id | Явный Retry, сохранить данные |
| 503 GET | error=upstream_unavailable, Retry-After: 2 | Ожидание минимум 2 секунды и явный Retry |
| Неожиданный HTTP/JSON | error/detail могут отсутствовать | Protocol/HTTP error, без падения |
| Сеть/таймаут GET | Ответ отсутствует | Явный Retry, не показывать empty |
| Сеть/таймаут/5xx POST | Результат может быть неизвестен | Предупреждение перед ручным повтором |

Срок ожидания вычисляется как Date.now()+Retry-After*1000. Положительное число секунд
принимается; дополнительно допустим HTTP-date. Невалидный/отсутствующий заголовок
при 429/503 дает консервативную паузу 2 секунды. Серверный срок не сокращается.
Общий retryAt проверяется перед любым новым вызовом, включая новый q.
Изменение текста/состава не сбрасывает cooldown. Нет автоматического polling/retry.

Таймаут fetch — 10 секунд; AbortController и timer освобождаются в finally.
Отмена устаревшего GET — не ошибка UI, его поздний ответ игнорируется.
Лимит сервера — 30 запросов в минутном окне на IP. Общий seq увеличивается
на запрос: на входе в список seq%9=0 дает 500; иначе seq%14=0 дает 503.
Ошибки имеют английские UI-сообщения; raw JSON, инструкции и телефоны не логируются.

## Наблюдаемый контракт функций src/api/

- listStops(query, options) → Domain-остановки; options содержит signal,
  необязательный progress (query/nextPage/collected) и onProgress после каждой
  успешной страницы. Одинаковый query может продолжить nextPage после ошибки;
  другой query начинается с page=1. Provider принимает progress только текущего
  requestId. Частичный список не выдается за полностью загруженный.
- createRoute(snapshot) → проверенный результат создания либо ApiFailure.
- HTTP/таймаут/JSON логика общая; ни одна функция не импортирует Context/экран.
- Подробные типы и классификация outcome: [data-model.md](../data-model.md).
