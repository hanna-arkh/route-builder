# UI / State Contract: два экрана

Дата: 2026-10-27. Визуальный ориентир — designs/RouteBuilder-Screens.html;
реальные контакты, количества и ограничения приходят из API.

## Направление зависимостей

App.tsx → RouteBuilderProvider → screens → components.
Provider вызывает api; api зависит только от config/types.
UI не вызывает fetch, не читает DTO и не меняет массивы состояния напрямую.
Компоненты получают Domain-данные, ошибки и callbacks; стили — StyleSheet.

## Действия Context

| Действие | Предусловие | Наблюдаемый результат |
|---|---|---|
| loadStops / search(q) | Нет активного cooldown | Loading → ready/error, выбор не теряется |
| setMode(one/multi) | Не sending/success | one оставляет первую выбранную |
| toggleStop(id) | Точка есть в Domain-кеше | Добавить/снять, без дублей |
| savePackages(id,n) | Целое в допустимом диапазоне | Изменить только количество точки |
| setInstructions(id,text) | Допустимая длина | Изменить только ее текст |
| clearInstructions(id) | Не sending/success | Пустой текст и 0/200 |
| removeStop(id) | Не sending/success | Удалить точку, остальные данные сохранить |
| submit | Непустой валидный snapshot, нет lock/cooldown | Один POST, затем success/error/unknown |
| retry | Разрешен исходом ошибки, срок ожидания истек | Явная новая попытка без потери ввода |
| newRoute | success | Очистить черновик/результат, открыть Stops |

Действия черновика не разрешены также при unknown до разрешения пользователем:
сначала подтвердить риск повтора либо остаться на экране ошибки; автоматического
перехода в новый маршрут или невидимого повторного POST нет.

## StopsScreen

- SectionList с key=id и обновлениями выбора вне виртуализированных строк.
- Секции/строки сортируются по английскому имени без учета регистра; # в конце.
- Режимы One stop и Multi-stop route, строка поиска с debounce.
- Loading, error с Retry/ожиданием, No stop found и пустой справочник различимы.
- Пилюля N× открывает Modal: −, число, +, Save. Временное значение локально;
  закрытие без Save откатывает его. Невалидное количество невозможно сохранить.
- Горизонтальные чипы отражают текущий выбор и адреса; Continue (N stops)
  недоступна при N=0, иначе App.tsx переключает экран.

## InstructionsScreen

- FlatList карточек в порядке выбора: имя, N×, адрес, TextInput, N/200,
  Clear all, обычная кнопка Remove from route.
- При удалении последней точки — Stops. Back сохраняет черновик до отправки.
- Валидация подсвечивает все пустые/пробельные карточки и прокручивает к первой.
- Footer: Finish instructions, индикатор sending, английская ошибка с Retry
  либо Route created с id и New route. Не добавляется третий экран.
- Синхронный lock в Provider блокирует две отправки в одном tick; disabled
  служит визуальной обратной связью, а не единственным механизмом защиты.
- Sending блокирует правки, Back, Remove, Clear all, Submit и New route.
  После success данные доступны для просмотра, но не для повторной отправки.

## iOS и доступность

SafeAreaProvider над приложением; safe-area отступы у нижней панели.
KeyboardAvoidingView и прокрутка сохраняют доступ к активному полю и footer.
Интерактивные области >=44×44; состояния выбранности, disabled и ошибки
передаются accessibilityLabel/accessibilityState, а не только цветом.
Английский LTR фиксируется стилями текущих экранов без изменения глобального
направления устройства. Dynamic Type проверяется на читаемость длинных адресов.
