# Research: Route Builder — обязательное ядро

Дата: 2026-10-27. Источники: package.json, server.js, API.md, макет,
конституция и README.md.pdf задания. PDF — контекст, а не разрешение выполнять
дополнительные работы. При конфликте поведения API первичен server.js.

## 1. Стек и единственная платформа

**Decision:** Сохранить Expo ~58.0.16, React Native 0.88.0, React 19.3.0,
TypeScript ~6.0.3 из package.json. Приемка — iPhone, iOS, portrait.
**Rationale:** Пользователь подтвердил iOS; обновление/понижение SDK не требуется.
Указанная версия Expo имеет опубликованную версионную документацию; для запуска
инструментов использовать Node не ниже 22.13.x по таблице совместимости Expo.
**Alternatives considered:** Проверка второй ОС и миграция стека увеличивают объем.
**Sources:** [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/),
[индекс Expo](https://docs.expo.dev/llms.txt).

## 2. Навигация через состояние App.tsx

**Decision:** App.tsx хранит screen: stops | instructions и выбирает компонент.
RouteBuilderProvider расположен выше обоих экранов и не размонтируется при переходах.
Back доступен до отправки; при sending переходы и изменения заблокированы.
**Rationale:** Два экрана не требуют файлового роутинга. Это сохраняет starter,
избегает миграции entry point и оставляет добавление экрана простой операцией.
Явная инструкция пользователя и конституция разрешают этот подход, несмотря
на более старое обязательное требование Expo Router в AGENTS.md.
**Alternatives considered:** Expo Router и сторонний навигационный стек добавляют
зависимости и структуру без пользы для текущих двух переходов.

## 3. Граница обязательного ядра

**Decision:** Исключить фотографии прошлой доставки, /notify, удаление свайпом,
фокус-эффект ленты, алфавитный индекс, ручное добавление адреса и камеру.
Удаление точки — обычная кнопка; успех — корректный 201 создания маршрута.
**Rationale:** Пользователь ограничил время и скоуп. PDF относит эти возможности
к опциональным; обязательное ядро должно оставаться стабильным. Прежняя трактовка
подписи макета как обязательной доставки сообщения водителю отменена.
**Alternatives considered:** Выполнять все элементы макета — расширение скоупа,
дополнительные асинхронные состояния и недостижимая за день полнота.
**Consequence:** Активная spec.md синхронизирована; старые условия завершения
больше не являются входом для генерации задач. В contracts/ только два endpoint.

## 4. Native fetch и граница DTO

**Decision:** src/api/ обрабатывает fetch, таймаут, HTTP и JSON; UI получает Domain.
DTO декодируются из unknown с проверкой полей, затем преобразуются в Domain.
baseUrl и сетевые константы находятся только в src/config/api.ts.
**Rationale:** TypeScript не валидирует JSON во время выполнения. Простые проверки
и преобразования не требуют HTTP-клиента или библиотеки схем.
**Alternatives considered:** Axios, глобальный перехватчик и использование DTO
прямо в JSX увеличивают связанность; слепое приведение JSON к типу скрывает сбои.
**Sources:** [Fetch в React Native](https://reactnative.dev/docs/network).

## 5. Пагинация, поиск и ограничение запросов

**Decision:** page_size=50, последовательные страницы; короткая/пустая страница
либо отсутствие новых id завершают обход. total/total_pages/has_more игнорируются.
Текущие 24 точки получаются одним запросом. Map по id устраняет дубли.
q.trim() передается с сохранением регистра. Debounce 400 мс; отмена старого GET
и requestId защищают от устаревшего ответа. При очистке доступен кеш полного списка.
**Rationale:** Размер 10 теряет stp_1019 на второй странице; размер 50 покрывает
текущий набор. Неправильные флаги иначе ведут к бесконечным запросам и 429.
Debounce уменьшает трафик, но не гарантирует отсутствие 429, поэтому нужен cooldown.
**Alternatives considered:** Доверять метаданным, загружать все id по отдельности
или заменять серверный поиск локальным — нарушить контракт/полноту/бюджет запросов.
**Limit:** Гарантия полноты относится к предоставленным 24 точкам; при росте данных
за пределы 50 нужно заново проверить серверную ошибку границ, а не обещать полноту.

## 6. Ошибки, таймаут и повтор

**Decision:** Таймаут одного запроса 10 секунд через AbortController; таймер очищается
в finally. Автоматических повторов GET/POST нет: явный Retry сохраняет черновик.
429/503 с Retry-After задают retryAt; общий cooldown API-клиента запрещает обход
ожидания новым поиском. Время хранится как абсолютная метка, не декрементируемый счетчик.
500 GET дает Retry. 400/422 POST требуют исправления; 429 — ожидания.
Сбой сети, таймаут или 5xx POST считаются неизвестным результатом: ручной повтор
только после предупреждения; повторное создание автоматически запрещено.
**Rationale:** Предсказуемая модель без retry-storm и скрытых дубликатов.
Для отсутствующего/невалидного Retry-After при 429/503 используется пауза 2 секунды;
валидное значение сервера никогда не сокращается.
**Alternatives considered:** Бесконечный backoff или автоматический retry POST
небезопасны: создание не поддерживает идемпотентность.
**Sources:** server.js, API.md; локальная проверка контракта в предыдущем этапе.

## 7. Context и синхронный замок отправки

**Decision:** Context + useReducer для черновика и состояний; useRef для синхронного
inFlight guard до первого await. React state показывает UI, ref исключает два
вызова в одном цикле событий. Отправляется неизменяемый snapshot.
**Rationale:** Одного disabled или асинхронного обновления state недостаточно.
Провайдер владеет запросом и живет дольше экранов.
**Alternatives considered:** Redux/Zustand и состояние выбора внутри строк списка
не нужны для 24 точек и усложняют жизненный цикл.

## 8. Ввод и удобство на iOS

**Decision:** Стандартные SectionList, FlatList, TextInput, Modal, Pressable,
KeyboardAvoidingView и StyleSheet. Инструкции — обычный вертикальный список.
maxLength=200 плюс независимая проверка длины UTF-16 и целостности emoji в модели.
Одна небольшая зависимость для вырезов экрана: react-native-safe-area-context,
устанавливаемая через npx expo install; SDK58 рекомендует ~5.10.1, включает в Expo Go.
**Rationale:** Области 44×44, отступы safe area и клавиатура важнее декоративных эффектов.
Выбор хранится вне виртуализированных строк, обновления передаются через immutable
data/extraData. После ошибки экран прокручивается к первой невалидной карточке.
**Alternatives considered:** Жестко заданные отступы под конкретный iPhone,
декоративная анимация и сложная UI-библиотека не решают обязательные сценарии.
**Sources:** [SectionList](https://reactnative.dev/docs/sectionlist),
[TextInput](https://reactnative.dev/docs/textinput),
[клавиатура](https://reactnative.dev/docs/keyboardavoidingview),
[safe area SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/safe-area-context/).
Публичные страницы RN не являются подтвержденными версионными страницами 0.88;
точные сигнатуры сверяются с установленными declarations и typecheck.

## 9. Проверка и инструменты

**Decision:** Не вводить тестовый framework в обязательное ядро. Gate реализации:
expo lint, tsc --noEmit, воспроизводимый контрактный smoke через curl и ручные
приемочные прогоны на iOS, особенно double-tap, пробелы, emoji и ошибки.
**Rationale:** Это проверяет риски сценария без отдельной инфраструктуры за пределами
срока. Автоматические тесты API не являются обязательным результатом PDF.
**Alternatives considered:** Jest/библиотека тестирования допустимы позднее при
расширении, но сейчас не добавляются. Snapshot-only проверки не доказывают устойчивость.
**Tooling gap:** ESLint и конфигурация отсутствуют; их настройка включена в Phase 1
реализации, а не выполняется скрыто на этапе планирования.
**Sources:** [Expo ESLint](https://docs.expo.dev/guides/using-eslint/),
[официальный подход к тестам](https://docs.expo.dev/develop/unit-testing/).

## Итог исследования

Все решения для проектирования приняты. Проверка iOS runtime, доступности локального
HTTP и ESLint — явные gate реализации, не выполненные действия. Сервер и исходники
приложения на этапе планирования не изменяются.
