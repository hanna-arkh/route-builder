# Feature Specification: Route Builder — обязательное ядро

**Feature Branch**: `001-build-route`
**Created**: 2026-10-26
**Updated**: 2026-10-27
**Status**: Accepted scope for planning
**Input**: Два экрана Stops и Instructions для диспетчера курьерского депо.
Английский интерфейс LTR, работа стоя одной рукой, проверка на iOS.

## Clarifications

### Session 2026-10-27

- По прямому указанию пользователя скоуп ограничен обязательным ядром задания.
  Эта редакция заменяет прежние условия завершения маршрута и зависимые от них
  сценарии. Успех означает подтвержденное создание через POST /v1/routes.
- Целевая ОС для приемки — iOS (подтверждено пользователем).
- Навигация — состояние в App.tsx. Новый маршрут начинается явным действием
  после успеха и очищает локальный черновик; серверный маршрут сохраняется.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Создать маршрут одной остановки (Priority: P1)

Диспетчер выбирает адрес, задает число посылок и инструкцию, создает маршрут.

**Why this priority**: Минимальный законченный рабочий сценарий.
**Independent Test**: Выбрать точку, сохранить две посылки, ввести инструкцию,
отправить маршрут и проверить подтвержденные данные.

**Acceptance Scenarios**:

1. **Given** открыт Stops, **When** справочник загружен, **Then** доступны все 24
   уникальные точки с буквенными секциями, инициалами, именем, адресом и телефоном.
2. **Given** One stop, **When** выбрана другая точка, **Then** предыдущая заменена;
   нижняя панель показывает выбранный адрес и Continue (1 stops).
3. **Given** открыта пилюля N×, **When** число изменено кнопками −/+ и сохранено
   через Save, **Then** новое количество сохранено; закрытие без Save его не меняет.
4. **Given** есть выбор, **When** нажат Continue, **Then** открыт Instructions
   с карточкой: имя, N×, адрес, инструкция, N/200 и Clear all.
5. **Given** инструкция корректна, **When** нажат Finish instructions и получен
   корректный ответ 201, **Then** показано Route created; завершенный черновик
   нельзя отправить повторно. New route открывает пустой Stops.

### User Story 2 - Подготовить несколько остановок (Priority: P1)

Диспетчер собирает маршрут, заполняет инструкции и удаляет лишнюю точку.

**Why this priority**: Полный маршрут не должен содержать дубли и пустые инструкции.
**Independent Test**: Выбрать три точки в Multi-stop route, заполнить инструкции,
удалить одну кнопкой и отправить оставшиеся две.

**Acceptance Scenarios**:

1. **Given** Multi-stop route, **When** выбраны три точки, **Then** видны три чипа,
   Continue (3 stops) и три карточки в порядке выбора; повторный выбор снимает точку.
2. **Given** инструкция пуста либо содержит только пробелы, **When** нажат Finish
   instructions, **Then** отправка блокируется, все проблемные карточки отмечены;
   остальные данные сохранены. После исправления ошибки исчезают.
3. **Given** инструкция заполнена, **When** нажат Clear all, **Then** очищается
   только текст этой карточки, счетчик становится 0/200.
4. **Given** есть карточки, **When** нажат Remove from route, **Then** точка
   исключена из выбора, чипов и отправки; остальные инструкции/количества сохранены.
5. **Given** заполнен черновик, **When** выполнен возврат на Stops и обратно,
   **Then** выбор, количество и текст сохранены в текущем сеансе.
6. **Given** выбрано несколько точек, **When** включен One stop, **Then** остается
   первая выбранная с ее текстом и количеством; возврат в Multi-stop route
   автоматически не восстанавливает снятые точки.

### User Story 3 - Найти точку и восстановиться после сбоя (Priority: P1)

Диспетчер ищет точку через сервис и отличает отсутствие результата от ошибки.

**Why this priority**: Быстрый поиск и сохранение выбора нужны в спешке.
**Independent Test**: Выполнить поиск с совпадениями и без, очистить запрос,
воспроизвести ошибку и повторить загрузку.

**Acceptance Scenarios**:

1. **Given** Stops, **When** введен q, **Then** показаны результаты сервиса;
   имя/адрес сопоставляются с учетом регистра, телефон — по минимум трем цифрам.
2. **Given** совпадений нет, **When** получено items=null, **Then** виден No stop
   found; выбранные точки не исчезают. Очистка поиска возвращает справочник.
3. **Given** старый ответ пришел после нового, **When** он обработан,
   **Then** список по-прежнему соответствует последнему тексту поиска.
4. **Given** загрузка/ошибка/пустой справочник, **When** открыт экран, **Then** видны
   разные состояния; Retry сохраняет выбор. При 429/503 соблюдается Retry-After.

### User Story 4 - Отправить без дублей и потери данных (Priority: P1)

Диспетчер видит загрузку, ошибку или подтвержденный успех создания маршрута.

**Why this priority**: Дубли маршрутов и потеря текста нарушают работу депо.
**Independent Test**: Десять быстрых нажатий запускают один запрос; после
подтвержденного отказа повтор не требует повторного ввода.

**Acceptance Scenarios**:

1. **Given** корректный черновик, **When** Finish instructions нажат десять раз
   до ответа, **Then** запускается одна отправка; виден индикатор, редактирование,
   возврат и повторный запуск недоступны до результата или таймаута.
2. **Given** подтвержденный отказ, **When** показана ошибка, **Then** выбор и текст
   сохранены, после исправления/ожидания доступен ручной Retry.
3. **Given** ответ потерян или результат неизвестен, **When** показана ошибка,
   **Then** нет автоматического повтора и ложного успеха; ручной повтор требует
   предупреждения о возможном уже созданном маршруте и явного подтверждения.
4. **Given** ответ 201 имеет неверный состав/текст, **When** выполняется сверка,
   **Then** нет ложного успеха или автоматического повторного POST; данные сохранены,
   показано предупреждение о необходимости проверки результата.

### Edge Cases

- N=0: Continue недоступна; удаление последней карточки возвращает на Stops.
- Количество — целое от 1 до packages_max, если максимум задан. Числовая строка
  и число означают одинаковый максимум; null не означает ноль.
- Лимит инструкции — 200 единиц UTF-16, включая пробелы; emoji не разрезаются.
  Лишний текст не принимается без обратной связи, введенный не теряется.
- page_size=50 покрывает текущие 24 точки за один ответ. Нельзя доверять total=25,
  total_pages=0, has_more=true; при необходимости продолжения страницы
  дедуплицируются по id. Ошибка страницы не считается пустым ответом.
- Повтор id не дает вторую строку/карточку; разные id с одинаковыми именами
  остаются разными точками. Поиск не снимает скрытые выбранные точки.
- Имена с неалфавитным первым символом относятся к #. Длинные данные и клавиатура
  не перекрывают активное поле и доступ к основным действиям.
- Некорректный ответ не вызывает падения и не маскируется под пустой список.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Два экрана Stops и Instructions MUST использовать английский LTR;
  приемка выполняется на одной ОС — iOS (все сценарии).
- **FR-002**: Stops MUST показывать весь доступный справочник, загрузку,
  ошибку с Retry и пустое состояние (US1.1, US3.4).
- **FR-003**: Строка MUST содержать инициалы, имя, адрес, телефон; сортировка
  и секции — по имени без учета регистра, прочие символы — # (US1.1, Edge Cases).
- **FR-004**: Поиск MUST использовать q сервиса, показывать отсутствие совпадений,
  игнорировать устаревшие ответы и сохранять выбор при очистке (US3.1–3).
- **FR-005**: One stop MUST разрешать максимум одну точку, Multi-stop route —
  уникальный набор; переключение сохраняет первую точку (US1.2, US2.1,6).
- **FR-006**: Пилюля N× MUST открывать −/число/+/Save. Количество MUST быть целым
  от 1 до заданного максимума; применяется только Save (US1.3, Edge Cases).
- **FR-007**: Нижняя панель MUST показывать горизонтальные чипы адресов
  и Continue (N stops); N — количество точек, не посылок (US1.2, US2.1).
- **FR-008**: Карточка MUST содержать имя, N×, адрес, поле, N/200 и Clear all;
  лимит 200 единиц UTF-16 MUST соблюдаться без повреждения emoji (US1.4, Edge Cases).
- **FR-009**: Clear all MUST очищать только свою инструкцию; отдельная кнопка
  Remove from route MUST исключать точку без потери других данных (US2.3–4).
- **FR-010**: Выбор, количество и инструкции MUST сохраняться при переходах,
  поиске и ошибках текущего сеанса (US2.5, US3, US4).
- **FR-011**: Пустой состав и пустая/пробельная инструкция MUST блокировать
  отправку; каждая проблемная карточка MUST иметь исправляемую ошибку (US2.2).
- **FR-012**: POST MUST содержать каждую выбранную точку ровно один раз,
  ее количество и неизмененный текст инструкции (US1–2).
- **FR-013**: Отправка MUST иметь синхронную защиту обработчика от double-tap,
  индикатор, блокировку кнопки, редактирования и переходов (US4.1).
- **FR-014**: Ошибки MUST сохранять черновик. При неизвестном результате
  автоматический повтор запрещен; ручной требует предупреждения (US4.2–4).
- **FR-015**: Успех MUST следовать только за корректным 201 с id, stops,
  status=draft и совпадением отправленных данных. Завершенный черновик
  повторно не отправляется; New route явно очищает его (US1.5, US4.4).
- **FR-016**: Основные области нажатия MUST быть не меньше 44×44 логических единиц;
  ввод и действия MUST быть доступны одной рукой с открытой клавиатурой (US1–4).
- **FR-017**: Бэкенд MUST оставаться неизменным; фактический server.js
  определяет контракт при расхождении с API.md (US3–4).
- **FR-018**: Запросы списка MUST использовать page_size=50, дедупликацию по id
  и завершение по данным страницы, а не ненадежным метаданным (Edge Cases).
- **FR-019**: 429/503 MUST соблюдать Retry-After; 400/422 требуют исправления,
  500/сбой сети дают понятную ошибку. Повторы MUST быть управляемыми (US3.4, US4).

### Key Entities *(include if feature involves data)*

- **Остановка**: id, имя, адрес, телефон, нормализованный максимум посылок.
- **Остановка черновика**: id остановки, целое количество, инструкция, порядок выбора.
- **Черновик маршрута**: режим выбора, упорядоченные уникальные точки; живет в памяти.
- **Результат создания**: подтвержденный маршрут с id/stops/status=draft либо
  отказ/неизвестный результат; не смешивается с текущим редактируемым черновиком.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 4 из 5 участников создают маршрут трех точек за 3 минуты стоя одной
  рукой с первой попытки; время ожидания сервиса исключается.
- **SC-002**: Пустая/пробельная инструкция в любой позиции всегда блокирует
  отправку и подсвечивает каждую проблемную карточку; исправление снимает ошибку.
- **SC-003**: В 20 прогонах десяти быстрых нажатий до ответа возникает один POST
  и не более одного созданного маршрута на прогон.
- **SC-004**: После каждого подтвержденного отказа выбор, количества и инструкции
  сохранены; успешный ручной повтор не требует повторного ввода.
- **SC-005**: При обратном порядке ответов поиска всегда показан последний запрос;
  очистка восстанавливает справочник без потери выбора.
- **SC-006**: Все видимые состояния двух экранов используют английский и LTR.
- **SC-007**: Каждый показанный успех соответствует id и полному совпадению состава,
  количеств и инструкций подтвержденного маршрута.
- **SC-008**: Доступны все 24 уникальные точки, включая 24/7 Pharmacy; загрузка
  завершается несмотря на неверные метаданные, пустой поиск показан корректно.
- **SC-009**: На границе 200/201 единиц и при emoji нет скрытой потери текста;
  строковый/числовой максимум одинаково ограничивают число, null не блокирует выбор.

## Assumptions

- Начальный режим — One stop, количество — 1. Порядок маршрута — порядок выбора.
  Clear all очищает только свою инструкцию. Текст перед отправкой не обрезается;
  trim применяется только для проверки заполненности.
- Continue (N stops) сохраняет заданную форму подписи при N=1. Сумма посылок,
  если отображается, вычисляется из выбора, а не берется из примеров макета.
- История, восстановление после перезапуска и офлайн-очередь не требуются.
  Область реализации исчерпывается двумя экранами и двумя операциями API ниже.
- iPhone portrait — целевое устройство; версия ОС должна поддерживать Expo SDK 58.

### Dependencies and Scope Boundaries

- [server.js](../../server.js), [API.md](../../API.md),
  [макет](../../designs/RouteBuilder-Screens.html); PDF задания прочитан как источник
  контекста. Приоритет имеют явное ограничение скоупа пользователем и реальный сервер.
- Используются только GET /v1/stops и POST /v1/routes. Сервис локальный, порт 4000,
  аутентификации нет. Адрес подключения зависит от iOS-устройства/симулятора.
- Визуальные данные берутся из сервера, значения и неверные секции макета не копируются.

### Service Contract and Error Rules

- GET /v1/stops: page с 1, page_size=50, необязательный q. Ответ
  {items,page,page_size,total,total_pages,has_more}; items — массив или null.
  Короткая/пустая страница завершает загрузку; полная требует следующей, данные
  дедуплицируются по id, отсутствие новых id также завершает обход.
- Метаданные заведомо неверны: total завышен на 1, total_pages округлен вниз,
  has_more иногда true даже на пустой странице. Размер 10 пропускает точку
  stp_1019 на границе страниц; выбран размер 50 для текущего справочника из 24 точек.
- q обрезается по краям; имя/адрес — регистрозависимое includes, телефон —
  вхождение цифр при минимум трех цифрах q. Локальная подмена поиска не нужна.
- packages_max — number, числовая string либо null. DTO также может содержать
  zone, last_delivery_at в ISO с/без Z либо Unix-секундах и notes=null/отсутствует;
  эти поля не нужны для обязательного UI и не интерпретируются как даты.
- POST /v1/routes: {stops:[{stop_id,packages,instructions}]} →
  201 {id,stops:[{stop_id,packages,instructions}],status:"draft"}.
  Сервер приводит число и молча обрезает инструкцию через slice(0,200);
  клиент проверяет заполненность, длину, уникальность и пределы заранее.
- Ошибки создания: 400 {error:"malformed_json"},
  422 {error:"validation_failed",fields:{stops:"required"}}.
- Лимит 30 запросов в минутном окне на IP: 429 {error:"rate_limited"}
  и Retry-After в секундах. При обращении к списку общий seq % 9 = 0 дает
  500 {error:"internal_error",request_id}; иначе seq % 14 = 0 дает медленный
  503 {error:"upstream_unavailable"}, Retry-After: 2. Счетчик общий для запросов.
- POST не имеет идемпотентности и операции чтения результата. При потере ответа
  возможен уже созданный маршрут; автоматическое пересоздание запрещено.

### Constitution Alignment

- I: Только клиент; сервер остается неизменным (FR-017).
- II: Реальный контракт, лимит 200 и ненадежные метаданные учтены явно.
- III: План разделяет UI, API-клиент и состояние; навигация не навязывает файловый роутинг.
- IV: Одноручный UX, обязательные инструкции, состояния ошибок и double-tap
  имеют требования и проверяемые сценарии.
